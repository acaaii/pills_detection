경계 주변 배경이 매번 바뀌기 때문일 것이라 추정은 되지만, 이 시점에서는 원인을 명확히 검증하지 않은 상태였다.

Algorithm 01

조명 합성 — 스크린 블렌드 기반

전경(알약)이 배경 위에서 실제로 그 자리의 빛을 받은 것처럼 보이게 하기 위해, 배경의 색과 밝기를 계산해 전경에 스크린(screen) 블렌드로 얹는 방식을 사용했다.

  1. 배경에서 알약이 놓일 영역의 평균 색상·밝기를 샘플링한다.
  2. 그 값을 조명 레이어로 변환해, 전경 위에 스크린 블렌드로 합성한다. 스크린 블렌드는 값을 밝히는 방향으로만 작동하기 때문에, 원본 알약의 하이라이트를 해치지 않으면서 주변광을 자연스럽게 얹을 수 있다.
  3. 결과적으로 알약이 그 배경 아래 실제로 놓여 있었던 것처럼 색 온도와 밝기가 배경과 맞춰진다.
Algorithm 02

그림자 합성 — 밝기 비대칭 기반 광원 추정

알약 표면 자체의 밝기를 관찰하면, 실제 촬영 조건을 역으로 추정할 수 있다. 한쪽은 밝고 반대쪽은 눈에 띄게 어둡다면, 빛이 밝은 쪽에서 어두운 쪽 방향으로 비스듬히 눕혀져 들어오고 있었다는 뜻이라는 가정에서 출발했다.

  1. 알약 표면의 밝기 분포를 측정해, 가장 밝은 지점과 가장 어두운 지점을 찾는다.
  2. 두 지점의 밝기 차이(ΔL)로 광원의 방향과 세기를 역산한다. 차이가 클수록 광원이 얕은 각도로, 뚜렷하게 들어온 것으로 판단한다.
  3. 추정된 방향의 반대쪽, 즉 알약이 눕는 쪽 바닥에 그림자를 렌더링한다. 밝기 차가 클수록 그림자를 더 길고 진하게 만든다.
밝기 비대칭 → 광원 방향 역산 → 반대 방향에 그림자 투영

최종 합성 결과 · 4개 알약

조명 + 그림자까지 반영된 최종 합성 이미지. 육안으로는 실제 촬영본과 거의 구분이 가지 않는다.

발견 — 성능이 이상할 만큼 빨리 오른다

아무리 자연스럽게 합성했다 해도, 합성 이미지는 실제 이미지보다 노이즈가 적다. 결국 모델이 학습한 것은 알약 자체의 특징이 아니라 경계(edge) 부분의 픽셀 패턴이었다. 합성 데이터만으로는 "너무 깨끗해서" 오히려 잘못된 신호를 학습하게 되는 셈이다.

→ 결론: 원본 train 데이터를 반드시 섞어야 한다. 합성 데이터가 실제 노이즈 분포를 대체할 수 없다.

발견 — class별로 뜯어보니

val 지표를 클래스별로 쪼개어 확인한 결과, 클래스 불균형이 매우 심각했다. 합성 3,000장 자체는 균형 잡혀 있었지만, 그중 800장을 random 추출하는 과정에서 균형이 깨진 것.

시도했지만 실패

추출 시점에 클래스 균형을 맞춰보려 했으나, 한 이미지 안에 3~4개 클래스가 동시에 들어 있는 구조라 장수 기준으로 비율을 역산하기가 쉽지 않았다. 여러 번 시도했지만 계속 불균형이 심하게 뽑혔다.

Next 01 · 재학습 없이 바로 적용 가능

NMS threshold 최적화 (IoU / confidence grid search)

NMS(Non-Maximum Suppression)는 한 객체에 대해 겹쳐서 검출된 여러 박스 중 confidence가 가장 높은 박스만 남기고 나머지를 억제하는 후처리 알고리즘이다. 이때 기준이 되는 두 값이 있다.

  1. IoU threshold — 두 박스를 "같은 객체의 중복 검출"로 판단하는 겹침 기준. NMS가 지우는 중복 박스는 실제로 두 가지 경우에서 나오는데, (a) 하나의 알약에 대해 모델이 grid cell·anchor 단위로 스스로 여러 박스를 뱉는 경우와, (b) 서로 붙어 있거나 겹친 두 물체를 모델이 헷갈리는 경우다. 우리 데이터는 알약끼리 물리적으로 겹치지 않기 때문에 (b)는 거의 발생하지 않고, 주로 (a) 때문에 NMS가 필요하다. 따라서 IoU threshold는 꽤 넓은 범위에서 안정적으로 동작할 가능성이 높고, 튜닝 우선순위는 상대적으로 낮다.
  2. Confidence threshold — 최종적으로 남길 박스의 최소 신뢰도. 낮추면 recall이 오르는 대신 오탐이 늘고, 높이면 반대로 정밀해지는 대신 놓치는 알약이 늘어난다. 겹침 여부와 무관하게 precision-recall 트레이드오프를 직접 좌우하는 값이라, 우리 도메인에서는 grid search의 실질적인 무게중심이 IoU threshold보다 이쪽에 있다.
  3. 그래도 두 값을 함께 val set에서 grid로 조합해가며 mAP가 가장 높은 지점을 확인하는 것 자체는 여전히 유효하다 — 다만 "알약이 겹쳐서"가 아니라 "모델이 같은 알약에 중복 박스를 내서" NMS가 필요하다는 점을 구분해서 접근한다.
Next 02 · 추론 단 개선

TTA (Test-Time Augmentation) + WBF

추론 시점에 원본 이미지 한 장만 넣는 대신, 같은 이미지를 여러 형태로 변형해서 함께 추론에 투입하고, 그 결과들을 다시 하나로 합치는 방법이다.

  1. Multi-scale — 이미지를 여러 해상도로 리사이즈해서 각각 추론한다. 알약마다 실제 크기 차이가 크기 때문에, 특정 스케일에서 놓치는 작은/큰 알약을 다른 스케일에서 잡아낼 수 있다.
  2. Flip — 좌우 반전한 이미지도 함께 추론한다. 모델이 특정 방향에 편향된 예측을 하고 있었다면, 반전 추론이 이를 상쇄해준다.
  3. WBF(Weighted Box Fusion) — 이렇게 얻은 여러 버전의 예측 박스들을 NMS처럼 "하나만 남기고 버리는" 방식이 아니라, 겹치는 박스들의 좌표와 confidence를 가중평균해서 새로운 박스를 하나 만들어낸다. 즉 NMS는 선택(selection), WBF는 좌표 자체를 개선(refinement)하는 방식이라 박스 정밀도 개선에 특히 효과적이다.
Next 03 · 여러 모델 결합

모델 앙상블 (2~3개 backbone/구조)

서로 다른 backbone이나 구조를 가진 모델 2~3개를 각각 학습시킨 뒤, 추론 결과를 함께 합친다.

  1. 구조가 다른 모델은 서로 다른 편향과 실수 패턴을 갖는다 — 한 모델이 놓치는 케이스를 다른 모델이 잡아내는 식으로 서로를 보완한다.
  2. 각 모델의 예측 박스를 모아, TTA에서 쓴 것과 동일한 WBF로 최종 박스를 산출한다. 즉 "여러 augmentation의 결과를 합치는 것"과 "여러 모델의 결과를 합치는 것"에 같은 융합 원리를 재사용하는 셈이다.
Next 04 · 도메인 특화 후처리

Bbox refinement — contour 기반 tight bbox 재계산

알약은 원, 타원, 캡슐형 등 형태가 단순하고 예측 가능하다는 도메인 특성을 그대로 활용하는 방법이다.

  1. 모델이 예측한 bbox 영역 안에서 segmentation mask를 얻는다 (SAM 등으로).
  2. 그 마스크의 contour(윤곽선)를 추출하고, 윤곽에 꼭 맞는 최소 외접 사각형을 다시 계산해 기존 bbox를 대체한다.
  3. Detection 모델이 뱉는 bbox는 실제로 여유 있게(느슨하게) 잡히는 경우가 많은데, 이렇게 윤곽 기반으로 조여주면 high IoU 구간(예: mAP50-95 중 IoU 0.75~0.95)의 정밀도가 크게 개선된다. 형태가 복잡한 객체보다 알약처럼 형태가 단순한 객체에서 특히 효과가 크다.
적용 예정 — 3차 재학습 결과가 나온 뒤 순차 적용

정리하면

  1. 합성 데이터가 자연스러울수록 좋은 것은 아니다. 노이즈가 너무 적으면 모델이 엉뚱한 것(경계 픽셀)을 학습한다.
  2. 원본 데이터는 대체 불가. 아무리 합성을 정교하게 해도 원본 train 혼합은 필수다.
  3. 클래스 균형은 생성 단계에서 잡아야 한다. 다중 클래스 이미지 구조에서는 추출 단계 후처리로 균형을 맞추기 어렵다.
  4. 이미 불균형한 원본이라면, 합성에서까지 다수 클래스를 더 늘릴 이유가 없다. class 0 제외는 그 결론에서 나온 결정이다.
  5. 데이터만으로 끝이 아니다. 3차 재학습과 별개로, NMS threshold 튜닝 → TTA+WBF → 모델 앙상블 → contour 기반 bbox refinement 순으로 후처리 단 개선도 함께 적용해볼 예정이다.
